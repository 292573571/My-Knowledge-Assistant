## 问题

质量评估器和 Eval 的区别是啥？

## 回答

质量评估器和 Eval 都用于评估 AI 回答，但职责不同：

| 项目 | RAG 质量评估器 | Eval |
| --- | --- | --- |
| 目的 | 保证当前这一次回答不要偏题、不要引用脏资料 | 衡量系统整体是否变好或退化 |
| 触发时机 | 每次真实用户提问时 | 开发、测试、发布前或定期批量运行 |
| 输入 | 当前问题、召回片段、当前模型回答 | 一组预设测试题、期望关键词、期望来源、拒答条件 |
| 输出 | 保留哪些来源，以及 PASS 或 FAIL | 通过率、评分、失败案例和评测报告 |
| 对当前用户的影响 | 直接影响本次回答是否携带本地引用或降级为模型补充 | 不直接影响单次在线回答 |

可以理解为：质量评估器是在线质检员，Eval 是离线考试系统。

质量评估器位于真实问答链路中：先筛掉无关、只有问题、带免责声明或不能支持答案的召回片段；模型生成答案后，再检查答案是否直接回答当前问题、关键结论是否有资料支持。评估失败时，不返回脏资料引用，而是降级为通用模型补充。

Eval 则使用一组标准测试题批量运行系统，例如检查“MCP 是什么？”是否包含预期关键词、是否引用正确资料、该拒答时是否拒答。它用于发现版本、模型、提示词、检索阈值或知识库变化造成的整体退化。

两者应同时保留：质量评估器防止线上单次事故，Eval 用于离线发现和持续修复系统性问题。需要注意，若质量评估器和回答使用同一个模型，它更擅长发现明显偏题和无关引用，不能保证完全判断复杂事实真伪。

## 问题

embedding是什么？

## 回答

**Embedding（嵌入）** 是一种将离散对象（如单词、句子、图像、用户等）映射到连续、低维向量空间的技术。在自然语言处理中，词嵌入（Word Embedding）将每个单词表示为一个稠密向量，使得语义或语法相似的单词在向量空间中距离更近（例如“国王”与“王后”的向量关系类似“男人”与“女人”）。常见的嵌入方法包括 Word2Vec、GloVe、FastText 以及基于上下文的 BERT 等。嵌入能够捕捉丰富的语义信息，是许多深度学习模型（如 RNN、Transformer）的基础输入表示。

## 问题

LLM是什么？

## 回答

LLM 是 **Large Language Model**（大型语言模型）的缩写。它是一种基于深度学习的人工智能模型，通过海量文本数据训练而成，能够理解和生成自然语言，完成对话、翻译、摘要、写作等任务。常见的例子包括 GPT、Claude、文心一言等。

## 问题

在大模型中，MCP是什么意思？

## 回答

在大模型（Large Language Models）中，“MMac”可能是指“Mixture of Experts”（专家混合模型），但通常与大模型直接关联的术语是“Mixture of Experts”（MoE）。

MoE 是一种模型架构，它将任务分解为多个子任务，并允许每个子任务由不同的“专家”子模型处理。这种架构可以提高模型的效率和性能，尤其是在处理复杂任务时。

## 问题

我想学习ai应用开发，应该先学习什么？

## 回答

学习 AI 应用开发，建议按以下顺序入门，优先建立可实践的路径：

1. **编程基础**：首选 Python，掌握变量、循环、函数、面向对象等基本语法。这是所有后续操作的工具，没有编程经验就从这里开始。
2. **理解 AI 基本概念**：了解机器学习、深度学习的基本流程（训练、推理、模型、数据集），不必深究数学，先建立整体认知。
3. **使用现成 AI 服务**：学习调用主流 API（如 OpenAI、Claude、Hugging Face），快速实现文本生成、图像识别等功能。这能让你立刻看到成果，保持学习动力。
4. **构建应用**：用 Flask 或 FastAPI 搭建 Web 服务，将 AI 功能集成进去，并了解简单部署（如云平台或容器）。这是从“调用”到“产品”的关键一步。
5. **深入框架**：根据方向学习 LangChain（LLM 应用）、TensorFlow/PyTorch（自定义模型）等，逐步扩展能力。

如果你已有编程基础，可以直接从第 2、3 步开始，边做边补缺。核心是先动手，再根据需要补充理论。

## 问题

我想用spring AI转AI应用开发，给我制定一套学习计划！

## 回答

好的，以下是一套从 Spring 生态转向 AI 应用开发的学习计划，基于 Spring AI 框架。由于 Spring AI 仍在快速迭代，部分 API 和功能可能随版本变化，建议始终以官方文档和示例为最新参考。

---

### 第一阶段：补齐 AI 基础概念（1–2 周）
**目标**：理解 AI 应用开发中常用的术语和原理，不要求深入数学，但要知道它们解决什么问题。

- **核心概念**：大语言模型（LLM）、提示词（Prompt）、补全（Completion）、嵌入（Embedding）、向量数据库、检索增强生成（RAG）、函数调用（Function Calling）、多模态。
- **推荐方式**：阅读 OpenAI 或 Cohere 的入门文档，观看直观的科普视频，动手调用一次 ChatGPT API 或 Hugging Face 的免费模型，感受输入输出。
- **注意**：不需要死磕算法，重点理解“如何与模型交互”以及“为什么需要 RAG/向量库”。

---

### 第二阶段：掌握 Spring AI 基础（2–3 周）
**目标**：能在 Spring Boot 项目中集成 Spring AI，完成基本的对话和提示词工程。

- **环境准备**：Spring Boot 3.x + JDK 17+，添加 `spring-ai-openai`（或其他提供商）依赖。
- **核心 API**：
  - `ChatClient`：同步/流式调用 LLM。
  - `Prompt` 与 `PromptTemplate`：结构化提示词，支持参数替换。
  - `OutputParser`：将模型输出转为 Java 对象（如 List、Map 或自定义 POJO）。
  - `ToolCallback` / Function Calling：让模型调用外部函数（如查询数据库、计算）。
- **实践**：写一个简单的聊天接口（流式输出），再做一个“根据用户输入生成结构化数据”的例子。
- **资源**：Spring AI 官方参考文档（`spring.io/projects/spring-ai`）和 `spring-ai-samples` GitHub 仓库。

---

### 第三阶段：深入 RAG 与向量存储（2–3 周）
**目标**：构建一个能基于自有文档回答问题的应用（RAG 模式）。

- **嵌入模型**：理解 `EmbeddingModel`，将文本转为向量。
- **向量数据库**：Spring AI 支持多种（Pgvector、Redis、Chroma、Weaviate 等）。选一个本地可运行的（如 Pgvector 或 Chroma）学习配置和 CRUD。
- **RAG 流程**：
  - 文档加载（`DocumentReader`）→ 分割（`DocumentSplitter`）→ 嵌入 → 存入向量库。
  - 查询时：嵌入用户问题 → 向量相似度搜索 → 将检索结果拼入 Prompt → 调用 LLM 生成答案。
- **实践**：做一个“知识库问答”应用，上传 PDF 或 Markdown 文件，提问后获得基于文档的回答。
- **注意**：RAG 的效果高度依赖分块策略和提示词设计，多实验。

---

### 第四阶段：进阶与生产化（持续）
**目标**：能根据业务需求定制 AI 功能，并考虑可靠性、成本和可维护性。

- **多模型切换**：配置多个 `ChatModel` Bean，根据场景选择（如小模型做简单分类，大模型做复杂推理）。
- **流式与响应式**：结合 Spring WebFlux 实现 SSE 推送。
- **评估与调优**：如何测试 Prompt 效果，如何记录 Token 消耗，如何设置超时和重试。
- **安全与合规**：敏感信息过滤、内容审核、数据隔离。
- **扩展**：学习 Spring AI 的 Adapter 机制，集成私有模型（如 Ollama 本地模型）或自定义模型。

---

### 总体建议
- **动手为主**：每学一个概念，立刻写一个最小可运行示例。
- **关注官方更新**：Spring AI 版本迭代快，GitHub 的 `spring-ai` 仓库的 `main` 分支常有新功能。
- **不要重复造轮子**：Spring AI 已经封装了多数 AI 提供商的 SDK，尽量使用其抽象，避免直接调用原始 API。
- **保持 AI 常识更新**：LLM 领域变化快，定期阅读技术博客或论文摘要，理解新趋势（如 Agent、MCP 协议等）。

如果你已有扎实的 Spring Boot 基础，这套计划大约需要 6–8 周完成前三阶段，之后便可独立开发常见的 AI 应用（智能客服、文档问答、内容生成等）。遇到具体问题时，欢迎继续提问。

以上回答基于通用大模型知识，不是当前知识库内容。
